# Разбор test_1.py: обработка комплексных сигналов передающего тракта

Этот документ объясняет фактический код `test_1.py` и вызываемые им функции из приложенного `psd.py`. Числа проверены запуском именно этих файлов на `test1_25p0.mat`. Ниже под «размерностью» отдельно понимаются форма массива, например `(43840,)`, и физические единицы, например Гц.

## 1. Зачем нужна обработка

В файле находятся входной сигнал передающего тракта `x` и измеренный приемником обратной связи выходной сигнал `y`. Их нельзя сразу вычитать: у приемника есть постоянное смещение, отличаются частоты настройки, выходная запись задержана, а амплитуда и фаза выхода отличаются от входа.

Обработка выполняется в таком порядке:

1. Вычесть постоянную составляющую приемника.
2. Перенести полезную полосу выходного сигнала к частоте входного.
3. Найти временную задержку и выделить соответствующий участок выхода.
4. Подобрать общий комплексный коэффициент амплитудного и фазового выравнивания.
5. Вычесть выровненные сигналы и рассчитать спектральную плотность мощности ошибки.

Один комплексный отсчет имеет вид `z = I + 1j*Q`. Действительная часть `I` — синфазная компонента, мнимая `Q` — квадратурная. Модуль `abs(z) = sqrt(I² + Q²)` задает амплитуду, а аргумент комплексного числа — фазу. Обработка ведется над комплексной огибающей, поэтому отрицательные частоты имеют смысл и их необходимо сохранять.

## 3. Загрузка и форма исходных данных

```python
mat = sio.loadmat('test1_25p0.mat')
x = mat['pdin']
y = mat['pdout']
tx_freq = mat['tx_freq']
rx_freq = mat['rx_freq']
```

`sio.loadmat` читает MAT-файл и возвращает словарь: имя переменной MATLAB служит ключом, массив с ее значениями — значением. В словаре есть также служебные записи вроде `__header__`.

| Переменная | Форма сразу после чтения | Тип данных | Содержание и единицы |
|---|---:|---|---|
| `mat` | Форма массива неприменима | `dict` | Словарь массивов и служебных данных |
| `x = mat['pdin']` | `(1, 43840)` | `ndarray`, `complex128` | 43 840 комплексных входных отсчетов |
| `y = mat['pdout']` | `(1, 65536)` | `ndarray`, `complex128` | 65 536 комплексных выходных отсчетов |
| `tx_freq` | `(1, 1)` | `ndarray`, `int64` | Частота передатчика, 3 410 000 000 Гц |
| `rx_freq` | `(1, 1)` | `ndarray`, `int64` | Частота приемника, 3 485 000 000 Гц |

`complex128` — комплексное число из двух 64-битных вещественных компонент. Из самих массивов нельзя установить калибровку в вольты или ватты: значения далее считаются в единицах отсчетов.

### Преобразование в одномерные массивы

```python
x = np.reshape(x, x.size)
y = np.reshape(y, y.size)
```

Свойство `.size` возвращает общее количество элементов: для `(1, 43840)` это `1*43840 = 43840`. `np.reshape` меняет форму массива, сохраняя значения и их порядок. Здесь получается:

```text
x: (1, 43840) → (43840,)
y: (1, 65536) → (65536,)
```

`(43840,)` — одномерный массив. Запятая — часть записи формы из одного измерения, а не признак второго измерения. В математических формулах такой массив условно представляем столбцом из 43 840 чисел, хотя NumPy не хранит у него направление «строка/столбец».

`len(x)` теперь возвращает 43 840, а `len(y)` — 65 536. До преобразования `len(x)` был бы равен 1, поскольку `len` считает элементы первой оси.

```python
tx_freq = tx_freq.item()
rx_freq = rx_freq.item()
Fs = 245.76E6
```

`.item()` извлекает единственный элемент массива как обычное число Python. Частоты становятся скалярами типа `int`, массивов `(1, 1)` больше нет. Запись `245.76E6` означает `245.76*10**6`, то есть 245 760 000. `Fs` имеет тип `float`, единицы — Гц, или отсчеты в секунду.

Закомментированные строки `float(np.reshape(tx_freq, 1))` не выполняются. Они оставляют перед преобразованием одномерный массив, что несовместимо с преобразованием в скаляр в используемой новой версии NumPy. `.item()` извлекает число явно.

Частоты настройки в MAT уже записаны в Гц. Их не нужно домножать на миллион. Частота дискретизации в этой записи MAT не хранится: `Fs` задана в скрипте по условию задания.

Интервал между отсчетами:

\[
T_s=\frac{1}{F_s}\approx4.0690104\text{ нс}.
\]

`Fs` не следует путать с частотой передатчика: 245,76 МГц определяет частоту отсчетов цифровой огибающей, а 3410 МГц — настройку радиочастотного передатчика.

## 4. Что рассчитывают X, Y, E и frq

```python
(X, frq) = psd.psd_welch(
    x, 2048, signal.windows.blackmanharris(2048), 1024, Fs
)
```

Функция возвращает два массива, которые распаковываются в `X` и `frq`. `X` — оценка спектральной плотности мощности входа, `frq` — соответствующие частоты. Аналогично `Y` относится к выходу, а `E` — к сигналу ошибки.

**Строчные `x`, `y`, `e` — комплексные сигналы во времени. Прописные `X`, `Y`, `E` в этом скрипте — вещественные значения СПМ в логарифмическом масштабе, а не комплексные результаты БПФ.**

### Параметры psd_welch

| Аргумент | Значение и форма | Смысл |
|---|---|---|
| `x` или `y` или `e` | Одномерный комплексный массив длиной `N` | Анализируемый сигнал; имя первого параметра внутри функции всегда `x` |
| `nfft` | Скаляр `2048` | Длина блока и БПФ, в отсчетах |
| `w` | Вещественный массив `(2048,)` | Оконные коэффициенты |
| `shift` | Скаляр `1024` | Шаг между началами соседних блоков, в отсчетах |
| `fs` | Скаляр `245760000.0` | Частота дискретизации в Гц; локальное имя параметра для внешнего `Fs` |

`signal.windows.blackmanharris(2048)` создает симметричное четырехчленное окно Блэкмана–Харриса. Это массив весов: около краев веса малы, в середине больше. При умножении блока на окно уменьшается скачок на его границах, что подавляет боковые лепестки и спектральное растекание. Цена — расширение главного лепестка: близкие частоты различать труднее. Окно безразмерно и не меняет число отсчетов.

Перекрытие блоков составляет `2048 - 1024 = 1024` отсчета, то есть 50%. Продолжительность блока — примерно 8,333 мкс, шаг по времени — примерно 4,167 мкс.

### Как устроен psd_periodogram

`psd_welch` вызывает из того же файла вспомогательную функцию:

```python
def psd_periodogram(x, w, fs, log_flag=True):
    n = len(x)
    wn = np.sum(w**2)
    X = (np.abs(np.fft.fft(x*w))**2) / (wn * fs)
    X = np.fft.fftshift(X)
    if log_flag:
        X = 10.0 * np.log10(X)
    frq = fs * np.arange(-n/2, n/2, 1) / n
    return X, frq
```

Разбор вычислений:

1. `x*w`: поэлементное умножение блока на окно, результат `(2048,)`, комплексный.
2. `np.fft.fft(...)`: быстрое вычисление дискретного преобразования Фурье. Комплексный результат `(2048,)` описывает вклад частотных составляющих блока.
3. `np.abs(...)`: модуль каждого комплексного коэффициента, вещественный массив `(2048,)`.
4. `**2`: квадрат модуля; получаем величину, пропорциональную мощности составляющей.
5. `wn = np.sum(w**2)`: сумма квадратов весов, положительный вещественный скаляр. Она учитывает изменение мощности при оконном взвешивании.
6. Деление на `wn*fs`: нормировка для получения спектральной плотности мощности. Линейные единицы — единицы отсчетов в квадрате на Гц.
7. `np.fft.fftshift`: перестановка двух половин спектра, чтобы отрицательные частоты были слева, нулевая в центре, положительные справа. Длина и значения элементов сохраняются, меняется порядок.
8. `10*np.log10(...)`: переход от линейной СПМ к логарифмическому уровню. Используется множитель 10, поскольку логарифмируется мощность. Для амплитудного коэффициента использовалось бы `20*log10`.

В `psd_welch` периодограммы вызываются с `log_flag=False`: сначала усредняются **линейные мощности**, и только затем берется логарифм. Усреднение готовых уровней в дБ дало бы другой результат.

Нулевая мощность математически дает `-inf` после `log10`. Для проверенных массивов эта особенность не мешает построению графиков. `log_flag` — логический скаляр `True` или `False`.

### Как устроен psd_welch

Функция проходит по сигналу блоками, рассчитывает периодограмму каждого, накапливает их сумму, делит на число блоков и переводит результат в дБ. Усреднение снижает случайные колебания оценки спектра.

В приложенной реализации последний неполный блок дополняется **комплексными нулями** до 2048 отсчетов и включается в среднее как отдельный блок. Для длины 65 536 получается 63 полных блока и один дополненный, всего 64. Для длины 43 840 — 41 полный и один дополненный, всего 42. Эта обработка остатка может давать небольшое отличие от стандартных реализаций Уэлча.

| Локальная переменная в psd_welch | Тип, форма и назначение |
|---|---|
| `n` | Целый скаляр, длина входного сигнала: 65 536 или 43 840. Не путать с внешним массивом номеров отсчетов `n` |
| `p` | Целый скаляр, индекс начала очередного блока: 0, 1024, 2048 и т. д. |
| `c` | Целый скаляр, счетчик включенных блоков: в итоге 64 или 42 |
| `X` | Сначала число 0, после первого сложения — вещественный массив `(2048,)`; сначала сумма линейных периодограмм, в конце СПМ в дБ |
| `X0` | Вещественная линейная периодограмма очередного блока, `(2048,)` |
| `frq` | Массив частот `(2048,)`, Гц |
| `tmp` | Комплексный буфер `(2048,)` для последнего неполного блока |

`np.zeros(nfft, dtype=complex)` создает нулевой комплексный массив. Присваивание `tmp[0:n-p] = x[p:n]` помещает остаток в его начало; конец остается нулевым. `while` повторяет обработку, пока помещается целый блок; `if` отдельно обрабатывает остаток. `return` возвращает результат вызывающему коду.

В `psd_periodogram` локальная переменная `n` равна 2048, а `wn` — вещественный скаляр. Локальная `X` проходит стадии комплексного БПФ внутри выражения, вещественной мощности и, при `log_flag=True`, уровня в дБ. Имена внутри функций не заменяют одноименные переменные основного скрипта.

`psd_correlogram` и `psd_bartlett`, также определенные в файле `psd.py`, из этого скрипта не вызываются. Импорты `plt` и `signal` внутри `psd.py` для используемых двух функций не нужны.

### Частотная ось и размер спектров

При любом из используемых размеров сигнала длина возвращаемого спектра равна длине БПФ:

```text
X.shape = Y.shape = E.shape = frq.shape = (2048,)
```

Все четыре массива имеют тип элементов `float64`. Частоты вычисляются как:

\[
f_k=F_s\frac{k-1024}{2048},\qquad k=0,\ldots,2047.
\]

Для данных параметров:

- шаг сетки `Fs/2048 = 120000` Гц = 0,12 МГц;
- первая частота −122,88 МГц;
- ноль имеет индекс 1024;
- последняя частота +122,76 МГц.

Верхняя точка +122,88 МГц не включается. Шаг сетки 120 кГц не равен точной способности разделить два тона: на нее влияет ширина главного лепестка окна.

`frq/1E6` создает массив той же формы `(2048,)`, переводя Гц в МГц. Значения `X`, `Y`, `E` уже логарифмические: брать от них еще один логарифм нельзя.

Подпись `dB/Hz` в коде обозначает логарифмическую СПМ относительно единичной мощности в принятом масштабе отсчетов. Без калибровки и сопротивления нагрузки это не дБм/Гц.

## 6. Шаг 1: удаление DC и Figure 2

```python
DC = np.mean(y)
y = y - DC
```

`np.mean(y)` суммирует все комплексные отсчеты и делит сумму на их количество:

\[
DC=\frac{1}{N_y}\sum_{n=0}^{N_y-1}y[n].
\]

`DC` — один комплексный скаляр `complex128`, в тех же единицах отсчетов, что `y`. Действительная часть оценивает постоянное смещение I, мнимая — постоянное смещение Q.

Для этого файла:

```text
DC = 45.24342346191406 + 18.650863647460938j
```

В `y - DC` NumPy автоматически вычитает одно число из каждого элемента массива. Это распространение скаляра по массиву называется broadcasting. Форма `y` остается `(65536,)`, тип — `complex128`. После вычитания среднее близко к нулю с точностью машинной арифметики.

Далее `Y` пересчитывается, сохраняя форму `(2048,)`. На Figure 2 узкий пик у 0 МГц исчезает. Основная полоса остается смещенной: этот шаг удаляет постоянную составляющую, а не исправляет частоты настройки.

DC удаляется до переноса спектра. Если сначала перенести частоту, исходная постоянная составляющая станет тоном на +75 МГц и вычитание среднего ее уже не уберет.

## 7. Шаг 2: перенос частоты и Figure 3

```python
delta_f = rx_freq - tx_freq
n = np.arange(len(y))
y = y * np.exp(1j * 2 * np.pi * delta_f * n / Fs)
```

`delta_f = 75000000` Гц — скаляр типа `int`, поправка +75 МГц. Полезная полоса после приемного преобразования имеет смещение `tx_freq - rx_freq = -75 МГц`, поэтому для компенсации нужен перенос с противоположным знаком.

`np.arange(len(y))` создает номера отсчетов от 0 включительно до `len(y)` не включительно: `0, 1, ..., 65535`. `n` — целочисленный массив `(65536,)`; в проверенном окружении тип элементов `int64`. Номер отсчета безразмерен.

Время каждого отсчета — `n/Fs`, массив `(65536,)` в секундах. Произведение `2*pi*delta_f*n/Fs` — массив фаз в радианах той же формы. `np.pi` — число π, `1j` — мнимая единица. `np.exp` поэлементно вычисляет комплексную экспоненту:

\[
e^{j\theta}=\cos\theta+j\sin\theta.
\]

Модуль каждого множителя равен 1: отдельная амплитуда отсчета не меняется, но его фаза получает добавку, растущую со временем. Это и переносит весь спектр:

\[
y_{\mathrm{freq}}[n]=y_{\mathrm{DC}}[n]
e^{j2\pi\Delta f n/F_s}.
\]

Экспонента имеет форму `(65536,)` и тип `complex128`. Знак `*` между массивами означает поэлементное умножение, не матричное. Обновленный `y` остается `(65536,)`, `complex128`.

На Figure 3 полезные полосы входа и выхода теперь совпадают по положению: приблизительно −50…+50 МГц. Разница уровней и внеполосные составляющие остаются. Частотный перенос не выполняет синхронизацию во времени и выравнивание усиления.

## 8. Шаг 3: синхронизация во времени и Figure 4

### График слева

```python
plt.figure(4)
plt.subplot(1, 2, 1)
plt.plot(np.abs(x))
plt.plot(np.abs(y))
```

`plt.subplot(1, 2, 1)` делит Figure 4 на одну строку и два столбца, выбирает левую область. `np.abs` преобразует комплексные отсчеты в вещественные амплитуды, сохраняя длину: для `x` получается `(43840,)`, для `y` — `(65536,)`.

Если `plot` получает только значения, горизонтальные координаты автоматически берутся как `0, 1, ..., N-1`. Здесь ось X — номер отсчета, ось Y — амплитуда в единицах отсчетов. Это не спектр.

Слева заметны разная длина записей и разные амплитуды. Задержку 174 отсчета на фоне всей записи в 65 тысяч точек различить трудно: для визуальной проверки отдельных пиков требуется увеличение участка.

### Поиск задержки

```python
cor = signal.correlate(y, x, mode='valid', method='fft')
delay = np.argmax(np.abs(cor))
```

Для наших массивов `mode='valid'` сравнивает `x` со всеми участками `y`, где `x` помещается полностью:

\[
cor[k]=\sum_{n=0}^{N_x-1}y[n+k]x^*[n],
\qquad k=0,\ldots,N_y-N_x.
\]

Звездочка — комплексное сопряжение. Функция выполняет его сама: передавать в `correlate` заранее сопряженный `x` не нужно.

Количество проверяемых положений:

\[
N_y-N_x+1=65536-43840+1=21697.
\]

Поэтому `cor.shape = (21697,)`, тип `complex128`. Значения имеют размерность произведения единиц отсчетов двух сигналов, суммированного по безразмерному индексу; нормировка на энергию внутри `correlate` не выполняется. `method='fft'` означает вычисление корреляции через БПФ для ускорения, а не поиск максимума спектра.

`np.abs(cor)` возвращает вещественный массив `(21697,)`. Модуль нужен потому, что неизвестная общая разность фаз поворачивает комплексную корреляцию. `np.argmax` возвращает **индекс максимального элемента**, а не его значение.

При данном порядке аргументов и режиме `valid` индекс максимума сразу равен задержке в отсчетах:

```text
delay = 174
delay/Fs = 0.7080078125 мкс
```

`delay` — целый скаляр; в проверенном окружении `np.int64`. Поиск целочисленный: дробная задержка этим кодом не оценивается.

### Обрезка выхода

```python
y = y[delay:delay + len(x)]
```

Срез включает левую границу и исключает правую. Здесь это `y[174:44014]`: берутся отсчеты исходной выходной записи с индексами 174…44013, всего 43 840.

```text
До среза:    x (43840,), y (65536,)
После среза: x (43840,), y (43840,)
```

Вырезается нужный участок: конец записи не переносится в начало. Это соответствует модели задания, в которой весь `x` содержится в более длинном `y`.

Внешний массив `n`, созданный на частотном этапе, остается длиной 65 536: срез `y` не меняет другие переменные. Далее `n` в скрипте не используется.

`plt.subplot(1, 2, 2)` выбирает правую область Figure 4. Там обе записи уже одинаковой длины, а соответствующие особенности огибающей совмещены по целому числу отсчетов. Разница амплитуд пока сохраняется. График `abs` не позволяет оценить фазовое совпадение.

## 9. Шаг 4: выравнивание по амплитуде и фазе

```python
g = np.sum(np.conj(y) * x) / np.sum(np.abs(y) ** 2)
y = y * g
```

Нужно найти одно комплексное число `g`, чтобы `y*g` было максимально близко к `x` по сумме квадратов ошибки:

\[
J(g)=\sum_n|x[n]-g\,y[n]|^2\longrightarrow\min_g.
\]

Число `g = |g|*exp(j*phi)` исправляет сразу два отличия: модуль масштабирует амплитуду, аргумент поворачивает фазу. Оно одинаково для всех отсчетов записи.

### Откуда взялась формула

Решение задачи наименьших квадратов:

\[
g=\frac{y^Hx}{y^Hy}
=\frac{\sum_n y^*[n]x[n]}{\sum_n|y[n]|^2}.
\]

`H` обозначает сопряженное транспонирование. Умножение строки `yᴴ` на столбец `x` дает сумму произведений соответствующих элементов. Аналогично `yᴴy` дает сумму `conj(y[n])*y[n]`, а каждое такое произведение равно `|y[n]|²`.

Из общей формулы лекции `w = (UᴴU)⁻¹Uᴴd` это получается подстановкой `U = y`, `d = x`, `w = g`. При одном коэффициенте `yᴴy` — матрица 1×1, то есть одно число; обращение превращается в обычное деление. Предполагается ненулевая энергия `y`.

Можно также раскрыть целевую функцию:

\[
J=x^Hx-gx^Hy-g^*y^Hx+|g|^2y^Hy.
\]

Приравнивая производную по сопряженному `g` нулю, получаем `-yᴴx + g*yᴴy = 0`, откуда следует та же дробь.

### Что делает каждая операция NumPy

| Выражение | Форма | Тип и смысл |
|---|---:|---|
| `np.conj(y)` | `(43840,)` | Комплексное сопряжение каждого отсчета: `a+jb → a-jb` |
| `np.conj(y) * x` | `(43840,)` | Комплексные поэлементные произведения |
| `np.sum(np.conj(y) * x)` | Скаляр | Комплексная сумма произведений, числитель |
| `np.abs(y)` | `(43840,)` | Вещественные модули выходных отсчетов |
| `np.abs(y)**2` | `(43840,)` | Вещественные квадраты модулей |
| `np.sum(np.abs(y)**2)` | Скаляр | Положительная вещественная энергия записи, знаменатель |
| `g` | Скаляр | Комплексный корректирующий коэффициент `complex128` |
| `y*g` | `(43840,)` | Комплексный выровненный выход |

`np.sum` без указания оси складывает все элементы. `**2` возводит каждый элемент в квадрат. Энергия записи `sum(abs(y)**2)` и средняя мощность `mean(abs(y)**2)` отличаются множителем длины. В формуле для `g` можно заменить обе суммы средними: при одинаковых длинах множитель сократится.

В масштабе одинаковых единиц отсчетов входа и выхода `g` безразмерен. Если каналы калиброваны в разных единицах, его единицы — отношение единиц `x` к единицам `y`.

Проверенные значения:

```text
g = 1.169875042496 - 0.966387088969j
20*log10(abs(g)) = 3.622018 дБ
angle(g) = -0.690430491 рад
```

Амплитуда выхода увеличивается примерно в 1,52 раза, фаза поворачивается приблизительно на −39,56°. Это коэффициент **выравнивания выхода к входу**, а не физическое усиление тракта в направлении вход → выход.

После `y = y*g` переменная `y` уже содержит результат коррекции. При расчете ошибки повторно умножать ее на `g` нельзя.

### Что видно на Figure 5

После нового расчета `Y` спектры входа и выхода в полезной полосе становятся ближе по уровню. Вне полосы выход остается выше входа: один коэффициент не устраняет спектральные искажения и шум.

Поворот фазы по спектру мощности непосредственно не виден: умножение на `exp(j*phi)` не меняет квадрат модуля БПФ. Таким графиком можно оценить амплитудное выравнивание; фазовая коррекция обеспечивается комплексной формулой `g`, а проверяется, например, сравнением действительных частей сигналов или величины комплексной ошибки.

В текущем коде Figure 5 ошибочно подписана как этап компенсации частотного смещения. Ее фактическое содержание — «После выравнивания по амплитуде и фазе».

## 10. Шаг 5: ошибка и Figure 6

```python
e = x - y
(E, frq) = psd.psd_welch(
    e, 2048, signal.windows.blackmanharris(2048), 1024, Fs
)
```

После предыдущего шага `y` уже выровнен, поэтому формула именно `e = x - y`.

`e` — комплексный массив `(43840,)`, `complex128`, в единицах отсчетов входа. Каждое значение — комплексная разница соответствующих отсчетов. Если бы выровненные сигналы совпали, `e` был бы нулевым.

`E` — вещественный массив СПМ ошибки `(2048,)`, `float64`. Хотя сигнал ошибки содержит 43 840 отсчетов, его спектр содержит 2048 точек: он рассчитан усреднением блоков с БПФ длины 2048.

Ошибка считается во времени до спектрального анализа. Выражение `X-Y` было бы разностью логарифмических уровней двух СПМ, а не СПМ разностного сигнала. В линейных спектрах ошибки есть также взаимный спектральный член, который нельзя получить простым вычитанием мощностей.

```python
plt.plot(frq/1E6, X, frq/1E6, Y, frq/1E6, E)
```

При стандартном стиле:

- синяя линия — СПМ входа `X`;
- оранжевая — СПМ выровненного выхода `Y`;
- зеленая — СПМ ошибки `E`.

В полезной полосе зеленая линия ниже входной и выходной, особенно в середине. Это показывает частичное совпадение сигналов после выравнивания. Разница уровней ошибки и входа меняется по частоте, то есть остаточные отличия неоднородны по полосе.

Вне полезной полосы мощность входного сигнала мала. Там `e = x-y` приблизительно равно `-y`, поэтому спектры ошибки и выхода почти совпадают. Знак минус меняет фазу на π, но не мощность.

По одной форме графика нельзя однозначно установить причину остатка. В нем могут присутствовать нелинейные и линейные частотно-зависимые искажения, шум, остаточная дробная задержка и другие несовпадения. Один скалярный `g` их все не устраняет.

Текущий заголовок Figure 6 также скопирован из частотного этапа. Фактический смысл этой фигуры — «Спектр сигнала ошибки».

### Дополнительная количественная оценка

Следующих строк в присланном скрипте нет; их можно добавить, если требуется одно число для ошибки:

```python
power_error = np.mean(np.abs(e) ** 2)
power_x = np.mean(np.abs(x) ** 2)
nmse_db = 10 * np.log10(power_error / power_x)
print('NMSE:', nmse_db, 'дБ')
```

Обе мощности — вещественные скаляры в единицах отсчетов в квадрате; их отношение безразмерно. `nmse_db` — логарифмическая относительная мощность ошибки, скаляр в дБ.

Для приложенных данных:

```text
Средняя мощность x:        19 966 730.9175
Средняя мощность ошибки:    2 962 863.7263
NMSE:                     -8.285953 дБ
```

Ошибка имеет около 14,84% средней мощности входа. Это отношение мощностей, а не процент амплитудной ошибки. Это также не автоматически EVM по символам или отдельная оценка только нелинейных искажений.
